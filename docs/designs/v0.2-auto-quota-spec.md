## 1. 为什么需要自动配额

在 v0.1 中，Token Watcher 仅支持纯手动的配额配置（用户手动输入总 Token 额度、已用 Token 与重置日期）。

### 1.1 用户痛点
1. **中转站额度变动频繁**：现代开发者频繁使用各种中转站（One-API / New-API / 开源自建 / 商业分销），账户余额随调用动态扣费，手动在 Token Watcher 里修改已用额度极为繁琐且很快失真。
2. **单位错位（Token 计数 vs 金额结算）**：中转站计费天然以金额（$USD / ¥CNY）或点数结算（各模型价格不同，无法折算为固定单一的 Token 数量），用户需要直观看到「账户充了 $50，已用 $12.35，剩余 $37.65」。
3. **安全与易用性平衡**：既要保持「不随意收集/泄露用户生产 Key」的底线，又希望当前正在使用的中转能够零配置一键感知余额，同时为多中转用户提供离线监控能力。

### 1.2 核心决策与工程安全边界
1. **中转站主流协议对齐与容错**：全面兼容覆盖市面 95% 以上中转站的 One-API / New-API 账单标准接口（`/v1/dashboard/billing/subscription` 与 `/v1/dashboard/billing/usage`），并支持 `/dashboard/billing/credit_grants` 备用降级。
2. **混合凭据策略与严格 SSRF 防护（P1-3 加固）**：
   - **当前激活档案零配置**：若档案未独立持久化 Key，且当前正是 `~/.claude/settings.json` 中激活的配置，在**严格保证目标请求 URL 的 Origin 与档案本身的 endpoint Origin 完全一致**的前提下，才允许借用当前环境变量/配置中的 Key。若用户配置了跨站的自定义 `quota_api_url`，严禁借用 settings Key，强制要求手动输入专用 Key！
   - **多档案自选持久化（P1-4 加固）**：用户可在卡片编辑面板为非活跃档案显式输入该中转专用的查询 Key（持久化至本地 SQLite，仅用于轮询账单）。数据库文件及配置目录权限显式收紧为 `0600`；所有 SQL 查询与 IPC 返回严格执行列名白名单，前端读取配置时 Key 绝不回显明文（脱敏处理）。
3. **单一切换与迁移兼容（P1-7 加固）**：
   - Schema V5 新增列为单一真源；旧字段 `quota_manual_*` 保持向前兼容；
   - 聚合层读取采用 `COALESCE(quota_total, quota_manual_total)`；
   - `update_profile_quota_config` 为唯一写入口。
4. **双单位自适应与诚实透支呈现（Meter Face 准则）**：
   - 手动配额支持 Token 计数模式；自动配额支持金额模式（`unit: "usd"` 或 `"cny"`）；
   - 超额透支（`used > total`）严禁封顶假装满格，真实显示透支比例（如 `118%`）与透支金额；
   - 遭遇接口失败时绝不抹除已有数值，保留旧值并标记错误状态徽标。

## 2. 双模型审查工程加固裁决清单（P0 ~ P2）

经由 Codex 与 agy 联合深度审查，针对草案存在的漏洞与边界问题作出统一裁决与加固：

### 2.1 协议健壮性与上游陷阱（P1-1, P1-2, P1-5）
1. **HTTP 200 错误信封拦截（P1-2 加固）**：
   - One-API / New-API 内部鉴权失败或错误时返回 HTTP 200 + `{"error": {...}}` 或 `{"message": "..."}`；
   - 响应解析器首步强制检查 JSON 根节点是否存在 `error` / `message`，严禁将错误体误判为有效账单数据。
2. **多货币与单位量级自适应（P1-1 加固）**：
   - New-API 支持切换为 CNY 或点数，One-API 支持禁用货币显示（返回原始 Quota 整数）；
   - 在编辑面板允许用户选定货币单位（`USD` 默认 / `CNY` / `Tokens`）；
   - 启发式量级校准：若返回的已用值包含小数，按美元/元单位处理；若为巨大整数（> 100,000）且明显超过总额 100 倍，自动进行 QuotaPerUnit 或美分换算。
3. **上限字段优先级与 0 值哨兵（Agy P1 加固）**：
   - 取值优先级：`hard_limit_usd` > `soft_limit_usd` > `system_hard_limit_usd`；
   - 哨兵处理：若上限为 0 或无限大，视为「不限额账户」，配额条不显示虚假 100%，而是显示「无上限」并单独呈现已用金额。
4. **子路径反代与 URL 归一化（P1-5 加固）**：
   - 若档案端点或用户填写的 `quota_api_url` 包含子路径（如 `https://proxy.com/api`），解析器保留原始路径前缀，分别尝试 `{base}/v1/dashboard/billing/subscription` 与 `{base}/dashboard/billing/subscription`。

### 2.2 架构、并发与系统安全（P1-3, P1-4, P1-6, P2-1 ~ P2-5）
5. **SSRF 防御与借用 Key 约束（P1-3 加固）**：
   - 仅当请求目标 Origin == 档案 endpoint Origin 时才允许借用 `settings.json` 的 Key；
   - 跨 Origin 强制要求显式提供专用 Key，拒绝将真实生产 Key 发送给未经验证的第三方。
6. **本地代理模式下的上游识别（P1-6 加固）**：
   - 当 Token Watcher 启用了本地代理时，`settings.json` 被注入为 `127.0.0.1`；
   - QuotaSyncer 检测到环回地址时，严禁向本地代理发起账单拉取，改从代理上下文（`proxy_state.saved_upstream`）获取真实上游 endpoint 进行匹配；
   - 非活跃档案若未配置独立 Key，显式标注 `sync_status = "inactive"`（暂停同步），绝不伪装为最新数据。
7. **多写者与存储生命周期安全（P2-1, P2-2, P2-5）**：
   - QuotaSyncer 必须在数据引擎（DataEngine）首扫完成并释放 DDL 锁之后才启动首轮轮询；
   - 每次网络拉取后，以独立的短生命周期连接写入 SQLite（设置 5s `busy_timeout`）；
   - `syncing` 仅为内存状态，禁止持久化到磁盘，防止进程退出后卡死；启动时自动清理历史残留；
   - 在途写入保护：回写时附加 `WHERE id = ? AND quota_type = 'api'` 条件，防止覆盖用户刚刚切换的手动配额。
8. **Single-Flight 防抖（P2-3 加固）**：
   - 采用基于 `tokio::sync::Mutex` 的并发控制，同一个 `profile_id` 正在拉取时，后续手动点击或轮询自动合并等待，严禁并发重入。

## 3. 详细技术规约

### 3.1 中转站账单接口探测与协议处理

针对目标 Base URL：
1. 剥离尾部重复的 `/v1`（若存在）；
2. 主探测链：
   - `GET {host_base}/v1/dashboard/billing/subscription`（或 `{host_base}/dashboard/billing/subscription`）
   - Header: `Authorization: Bearer <key>`
   - 校验：必须为 HTTP 2xx 且无 `error` 键；
   - 提取 `hard_limit_usd` / `soft_limit_usd` 及 `access_until`（秒级时间戳转换为 `YYYY-MM-DD`）；
3. 联动提取 Usage：
   - `GET {host_base}/v1/dashboard/billing/usage?start_date={start}&end_date={end}`
   - `start_date`: 当月 1 号（`YYYY-MM-01`）；`end_date`: 明天（`YYYY-MM-DD`）；
   - 提取 `total_usage`：若为美分换算为 `/ 100.0`；若为标准美元直接采用；
4. 降级备用链路：
   - 若上述 404，探测 `GET {host_base}/dashboard/billing/credit_grants` 或 `/api/dashboard/billing/credit_grants`。

### 3.2 数据库 Schema V5 迁移

在 `src-tauri/src/core/store.rs` 中：
```sql
-- Schema V5
ALTER TABLE profiles ADD COLUMN quota_type TEXT NOT NULL DEFAULT 'manual'; -- 'manual' | 'api'
ALTER TABLE profiles ADD COLUMN quota_unit TEXT NOT NULL DEFAULT 'usd';    -- 'usd' | 'tokens' | 'cny'
ALTER TABLE profiles ADD COLUMN quota_api_url TEXT;                        -- 自定义 billing url
ALTER TABLE profiles ADD COLUMN quota_api_key TEXT;                        -- 档案持久化 Key（脱敏展示）
ALTER TABLE profiles ADD COLUMN quota_total REAL;                          -- 统一总额度
ALTER TABLE profiles ADD COLUMN quota_used REAL;                           -- 统一已用额度
ALTER TABLE profiles ADD COLUMN quota_updated_at INTEGER;                  -- 上次同步时间（毫秒）
ALTER TABLE profiles ADD COLUMN quota_sync_status TEXT;                    -- 'ok' | 'error' | 'inactive'
ALTER TABLE profiles ADD COLUMN quota_sync_error TEXT;                     -- 简短错误信息

-- 数据平滑填充
UPDATE profiles 
SET quota_total = quota_manual_total, 
    quota_used = quota_manual_used,
    quota_unit = 'tokens'
WHERE quota_manual_total IS NOT NULL AND quota_total IS NULL;
```

### 3.4 UI 交互与视觉规范

1. **状态标签与刷新交互**：
   - 手动配额：保留 `[手动]` 标签；
   - 自动配额：显示 `[API $]`（或 `[API ¥]`）等宽标签；
   - 刷新按钮：在标签旁提供轻量无边框微型刷新按钮 `↻`：
     - 点击触发同步，执行旋转动效；
     - 同步中禁用；
     - 状态异常显示警告图标 `!`，Tooltip 呈现 `sync_error`；
     - 状态为 `inactive`（未激活无 Key）显示淡灰图标，提示「当前未激活，请先切换或配置独立 Key」；
2. **超额透支呈现（Meter Face 诚实原则）**：
   - 当 `used > total`：
     - 配额条满格并叠加 45° 警示斜线纹理；
     - 文字显示：`已用 $62.00 / $50.00 (124%) · 透支 $12.00`；
   - 当 `used <= total`：
     - 显示：`已用 $12.35 / $50.00 (24.7%) · 剩余 $37.65`；
3. **编辑弹窗扩展**：
   - 模式切换：`手动输入` 与 `中转站 API 自动同步`；
   - 自动模式下支持填入自定义 API 地址与专属 Key，并提供「测试连接」按钮就地校验。
