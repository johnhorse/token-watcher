## Problem Statement
随着 2026 年自主编程 Agent 与大模型编程工具的爆发，开发者日常高频切换于多个不同厂商的 AI 编码环境中：
- 谷歌官方新一代编程工具 **Google Antigravity**（桌面版 + `agy` CLI，搭载 Gemini 3.8 / 3.0）；
- 国内主流自研 Agent：智谱 **ZCode**（搭载 GLM-5.3 编程专项大模型）、阿里 **Qoder**（通义灵码团队打造）、腾讯 **WorkBuddy**（CodeBuddy 架构演进）。

现有 token-watcher（v0.6.1）已支持 Claude Code、Codex CLI、Cline、Roo Code、Aider、OpenCode、Continue.dev、omp 共 8 款工具。然而，上述 4 款最新主流工具的会话消耗无法被统一观测。更关键的痛点在于：
1. **思维链黑盒（Thinking Iceberg）**：Gemini 3.8、GLM-5.3、Codex 等新一代思考模型在生成时产生庞大的 CoT（Chain of Thought）思维链 Token，用户在界面上只看到短短十几行代码，背后实际消耗了数万 Token，费用与额度消耗缺乏透明度；
2. **多端数据割裂**：同品牌工具桌面端与终端 CLI（如 Antigravity 桌面与 agy CLI 共享 `~/.gemini/antigravity/`，ZCode 客户端与 zcode CLI 共享 `~/.zcode/`）虽共用数据根，但缺乏统一多源管理；
3. **数据格式异构**：Antigravity 采用 SQLite 存储 Protobuf 二进制元数据，ZCode 在 JSONL 中兼有包含式与排他式用量并自带精确毫秒耗时，Qoder/WorkBuddy 采用项目级 JSONL 流。缺乏统一的四维归一化与只读增量接入标准。

## NOT in Scope
- **字节跳动 Trae**：经现场对 `Trae CN/User/workspaceStorage/*/state.vscdb` 实地深度逆向取证证实，Trae 本地 SQLite 仅记录 UI 对话文本与插件状态，未将任何 Token 数量落盘；且 token-watcher 现有的 `proxy.rs` 仅为 Claude Code 专用的反向代理（监听 4040 端口嗅探消息 ID），不存在通用前向嗅探能力。本版本坚决不写投机解析代码，明确排除 Trae 直读，避免破坏 D22 幂等性。
- **Cursor / Windsurf**：同属本地不存 Token 数量的云端计费体系，待后续独立网络透明代理专项攻关，不在 v0.7.0 本地离线直读范围内。

## What Already Exists
- **SQLite 只读连接与游标模式**：复用 `core/ingest.rs` 中成熟的 OpenCode SQLite 读取经验（`SQLITE_OPEN_READ_ONLY | SQLITE_OPEN_URI` + `PRAGMA query_only = ON;` + `PRAGMA busy_timeout = 3000;`），直接应用于 Antigravity 的 `conversations/*.db`。
- **JSONL 流式增量消费**：复用 `omp` 与 `ClaudeCode` 的 `JsonlDir` 字节位移 Checkpoint 机制，直接应用于 ZCode、Qoder、WorkBuddy。
- **Schema v6 耗时基座**：v0.6.1 已上线的 `duration_ms` 字段与两轮平均生成速率模型，无缝承接 ZCode 原生毫秒耗时。

## What Makes This Cool
1. **Thinking Iceberg™（思维链冰山模型）**：
   - 行业首个将 AI 隐藏思考成本透视化的桌面工具。
   - 提取 Google Antigravity 原生 `thoughts_token_count` 与 GLM-5.3 推理用量，在看板和卡片小组件中直观呈现「思维链占比」（支持思考链引擎聚合公式：`thinking_share = sum(thoughts_tokens) / sum(output_tokens)`；未产生思考 Token 的引擎显示 `N/A`，例如："Gemini 本周产出 2.1M Token，其中 84% 发生在背后深层思考"），将抽象的 Token 账单转化为震撼的认知体感。
2. **本地二进制 Protobuf 零侵入透明解密**：
   - 无需 Google Antigravity 提供官方导出，通过内置轻量级无依赖 `ProtobufReader` 直接穿透解析本地 `gen_metadata` 中的 Protobuf 字段，精准解出 Gemini 的 4D Token 与思维链，配合 `PRAGMA busy_timeout = 3000;` 与快照降级（`copy_and_read`）做到安全无阻读。
3. **原生耗时与真实生成速率（Schema v6 联动）**：
   - 直接摄取 ZCode 的 `durationMs` 原生单轮耗时，彻底摆脱跨轮次时间戳估算误差，在 HUD 胶囊与托盘实时呈现最真实的 tokens/s 生成心跳。
4. **全景跨引擎工控微徽标矩阵**：
   - 徽标矩阵拓展至 12 款主流引擎，新增 `[Antigravity]`（极光红紫）、`[ZCode]`（智谱蓝）、`[Qoder]`（阿里橙）、`[WorkBuddy]`（腾讯企鹅青），支持按引擎一键切片下钻。

## Constraints
1. **被动只读与并发安全**：被动文件接入路径绝对不以代码注入修改宿主进程；对 SQLite 文件采用只读连接（`SQLITE_OPEN_READ_ONLY | SQLITE_OPEN_URI`）、`PRAGMA query_only = ON;` 以及 `PRAGMA busy_timeout = 3000;`，若遇写权限限制或缺少 `-shm`，自动启用只读快照副本（`copy_and_read`）。
2. **轻量无额外 Heavy Crate**：Protobuf 解析采用手工解码 Wire 格式（Varint + Tag Walk），不引入沉重的 `prost-build` 或外挂 C 库，保证安装包极小（保持当前 ~10MB 级别体积）。
3. **D24 包含式与排他式互斥保护**：针对 ZCode 等 `response.usage.inputTokens` 包含缓存的工具，全链路统一严格执行 `net_input = inputTokens.saturating_sub(cacheReadTokens + cacheWriteTokens)`，彻底杜绝双计。
4. **全链路注册联动**：必须在 5 大注册点（`agg.rs` 的 3 处 SQL 过滤分支、`ingest.rs` 的 `detect_file_kind`、`store.rs` 的 `is_isolated_engine` 隔离列表）全量注册，严防新引擎用量意外滑入 Claude 默认切片。

## Premises
1. **被动只读优先**：默认基于本地落盘（SQLite/JSONL）增量探测，对 Antigravity 等 SQLite 数据库采用纯只读与 WAL/busy_timeout 隔离，绝不与宿主进程发生死锁；
2. **四维统一归一化 + 思维链持久化**：Gemini 的 prompt/candidate/cache 与智谱/阿里/腾讯字段统一映射到 input/output/cache_read/cache_creation；引入 Schema v7 迁移持久化 `thoughts_tokens`（作为 `output_tokens` 的思考子集，`thoughts_tokens <= output_tokens`），原生携带的 durationMs 赋给 Schema v6 `duration_ms`；
3. **CLI 与桌面融合归集**：
   - Antigravity：桌面 App 与 agy CLI 共用 `~/.gemini/antigravity/`，统一徽标为 `[Antigravity]`；
   - ZCode：桌面端与 zcode CLI 共用 `~/.zcode/`，统一徽标为 `[ZCode]`；
   - WorkBuddy：桌面版与 CodeBuddy CLI 共用 `~/.codebuddy/`，统称与徽标为 `[WorkBuddy]`；
   - Qoder：客户端与 qodercli 共用 `~/.qoder/`，统一徽标为 `[Qoder]`；
4. **静默容错**：未安装的工具静默跳过，坏行与未识别版本平滑丢弃，绝不影响主监控循环。

## Architecture & Data Flow

```
[ Antigravity ] -> ~/.gemini/antigravity/conversations/*.db (SQLite)
                      \-- gen_metadata (Protobuf: f1.f4 -> tokens + thoughts)
                      \-- steps (Protobuf: Timestamp)

[ ZCode ]       -> ~/.zcode/cli/rollout/model-io-session_*.jsonl
                      \-- response.usage (Inclusive tokens -> D24 saturating_sub)
                      \-- durationMs -> duration_ms

[ Qoder ]       -> ~/.qoder/projects/**/*.jsonl
                      \-- message.usage (Claude-Code compliant)

[ WorkBuddy ]   -> ~/.codebuddy/projects/**/*.jsonl
                      \-- usage (4D tokens + model)

        |
        v
[ Ingest Dispatcher (ingest.rs) ] -> FileEngineKind
        |
        v
[ Core Storage (store.rs) ]       -> Schema v7: usage_records (thoughts_tokens)
        |
        v
[ Aggregation (agg.rs) ]          -> Thinking Iceberg (thinking_share) + Engine Slices
        |
        v
[ Desktop HUD & Tray (Tauri) ]    -> [Antigravity] [ZCode] [Qoder] [WorkBuddy] 徽标
```

## Failure Modes & Mitigations
1. **Antigravity WAL 写入中锁表**：
   - 现象：宿主正在高频写，token-watcher 尝试读抛出 `SQLITE_BUSY`。
   - 应对：设置 `PRAGMA busy_timeout = 3000;`；若重试超时，启动 `copy_and_read`（复制到系统临时目录作为静态快照读取），绝不挂起或崩溃。
2. **ZCode 缓存读取数大于总输入（脏数据）**：
   - 现象：输入数据异常导致 `cacheReadTokens > inputTokens`。
   - 应对：使用 `saturating_sub`，保底结果为 0，防止 Rust 算术溢出 panic。
3. **缺失 `-shm` 共享内存文件写权限**：
   - 现象：在受限沙箱或无写权限目录打开 SQLite WAL 模式数据库。
   - 应对：捕获 open 错误，自动切换到内存/临时目录快照模式。

## Worktree Parallelization Strategy
- 模块耦合度：后端解析与存储属于强约束链路，前端组件依赖后端字段。
- 策略：分两阶段推进：
  - **Lane 1 (后端核心闭环)**：`store.rs` Schema v7 -> `parse.rs` (ProtobufReader + 4 个解析器) -> `ingest.rs` & `watch.rs` 注册 -> `agg.rs` 聚合与定价 -> 自动化测试 `t20_engine_expansion_v3.rs`。
  - **Lane 2 (前端界面呈现)**：`types.ts` -> `EngineChips.svelte` -> Thinking Iceberg 看板卡片。
