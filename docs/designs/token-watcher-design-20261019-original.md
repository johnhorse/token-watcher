## Problem Statement

VibeCoding 开发者（Claude Code 重度用户）烧 token 如流水，却看不到消耗：现有工具要么是终端里的事后报表（ccusage、tokscale），要么是 macOS-only 的菜单栏配额条（ClaudeUsageBar、TokenEater、TokenBar）。没有一个工具同时满足：macOS + Windows 双平台、实时（秒级）图表、桌面 HUD 形态、多语言。更具体的痛点：**多订阅/中转用户**（如通过 CC Switch 在 Anthropic 官方、DeepSeek、Kimi 等中转间切换的用户）无法知道每个订阅各烧了多少、配额还剩多少——Claude Code 本地会话文件里根本没有这个字段。

作者本人就是目标用户（「统计 token 消耗的维度是否可以支持按照不同订阅（或订阅地址）进行统计，配额根据不同订阅地址进行获取或者配置」）。

## What Makes This Cool

- **心电图式实时折线**：平线=空闲、尖峰=AI 正在生成、缺口=无观测时段——token 消耗第一次变成「看得见的生命体征」
- **订阅归因**：监听 settings.json 变化 + 时间戳关联，把每条用量归到当时的订阅档案（推断，标注），多中转用户第一次看清每个后端的消耗
- **诚实仪表美学**（Meter Face）：唯一信号色琥珀只给测量数据；预估/估算用 45° 斜线纹理表示（不靠颜色、不靠图例）；无红绿评判色——表只报告，不训人
- **形态切换**：菜单栏+悬浮窗 ↔ 桌面角落 HUD（游戏 FPS 计数器感），一种数据两种存在方式

## Constraints

- 双平台：macOS + Windows（Tauri v2，系统 WebView：WKWebView / WebView2）
- 小巧低占用：包体目标 <10MB；空闲 CPU≈0（fs 事件驱动，无轮询）；常驻内存目标 <150MB（含 WebView）
- 技术栈：Rust（core 数据引擎）+ Tauri v2 + Svelte 前端（用户指定 Rust 或 Go，选 Rust，理由见 Approaches）
- i18n：中文/英文，默认跟随宿主机语言；暗色模式默认跟随系统
- 纯开源社区工具，不商业化（本期）
- v0.1 数据源只做 Claude Code 本地 JSONL（~/.claude/projects/**/*.jsonl）

## Premises（全部经用户确认）

1. 品类空位真实存在（双平台+实时+图表+HUD+i18n 组合无人占据），值得做开源工具
2. v0.1 数据源 = Claude Code 本地 JSONL + 监听 ~/.claude/settings.json 的 env 变化做订阅归因；本地代理模式（归因精确到请求）为 v0.2 可选增强
3. **订阅归因是推断不是事实**（Codex 修正，用户已接受）：正在运行的会话可能仍用旧中转；UI 必须显示未知时段、支持手动修正；装工具前的历史无法回溯归因
4. 四个统计维度：会话 / 模型 / 程序（entrypoint）/ 订阅档案。token 四项直读 usage 字段（input / output / cache_read / cache_creation）；成本按 LiteLLM 价格表估算（UI 标注「估算」）；配额按档案类型：官方=启发式估算（5h 窗口+周额度）、中转=可配 billing 接口或手动填额度——一律标注「估算/手动」
5. 自建 SQLite 聚合存储，历史不受 Claude Code 默认 30 天会话清理影响
6. 分发走 GitHub Releases + CI 双平台构建；代码签名/公证后置（接受首次打开的 Gatekeeper/SmartScreen 提示）
7. 主题策略：design tokens（CSS custom properties）day one；v0.1 单默认主题；v0.2 主题切换器 + 另两套预设，社区可贡献

## Cross-Model Perspective

**Codex 冷读**（第二意见，已采纳两条）：①「flight recorder（飞行记录仪）」——把会话/模型切换/订阅切换/缓存命中画在同一条时间轴上，回放昨天的工作（进 v0.2 旗舰视图）；②设计修正：settings.json 变化≠运行中会话实际用的中转，归因必须标注推断+支持手动修正（已进 Premise 3）。其周末原型建议（垂直切片：notify+serde+rusqlite、增量 tail+checkpoint+去重、先菜单栏后 HUD）被 Approach B 采纳。

**三方美学合成**（Codex「安静仪器」/ agy-Gemini「Calibrated Slate」/ Claude 子代理「Meter Face」）：
- 三方共识（直接进规范）：石墨底非纯黑；唯一强调色只给测量数据；拒绝发光/blur/霓虹；机械式短动效（80-240ms，无弹簧无滚轮）；折线线性连接保留尖峰；LIVE 是状态不是装饰；CJK 走系统字体
- 分歧点是气质（暖+琥珀 vs 冷+青绿），用户选择 **Meter Face 合成版**为默认主题（见 Recommended Approach），Calibrated Slate 与 Mint Pulse 进 v0.2 预设

## Approaches Considered

### Approach A: 全功能一步到位（Rust+Tauri，三形态+成本+配额 v0.1 全做）
被否——首版战线太长（human ~3-4 周），HUD 透明窗与数据管道耦合互相拖累，烂尾风险高。

### Approach B: 垂直切片先行（Rust+Tauri，v0.1 只做可信数据管道+菜单栏/悬浮窗）✅
被选——数据可信是命根（口径混乱正是 ccusage 被吐槽的点）；每层独立可验证；HUD、成本估算、自动配额进 v0.2（手动额度配额条 v0.1 随订阅档案交付），数据层零返工。

### Approach C: Go + Wails（功能同 B）
被否——Wails 的 tray + 透明置顶窗（HUD 核心需求）支持弱于 Tauri，Windows 边角问题多；GC 常驻内存高一档。若后续证明 Rust 维护负担过重可重新评估。

## Recommended Approach

**Approach B：垂直切片先行**。数据层与 Approach A 完全一致，分期只影响 UI 形态交付节奏。

### 架构（v0.1）

```
~/.claude/projects/**/*.jsonl ──notify(FSEvents/ReadDirectoryChangesW)──┐
~/.claude/settings.json ──watch(env 变化→订阅档案时间线)────────────────┤
                                                                        ▼
                    Rust core：增量 tail（byte-offset checkpoint）
                    → 行级解析（容忍不完整尾行/截断/轮转）
                    → 去重（message uuid + 更新语义）
                    → SQLite（usage_records / file_checkpoints / profile_timeline 三表同事务提交）
                    → Tauri event push
                                                                        ▼
                    Svelte 前端：菜单栏项 + 悬浮窗（380×560）
```

- crates：notify、serde/serde_json、rusqlite；UI 经 Tauri tray/window API
- 永不持久化认证 token；settings.json 只读 env 键名与 base URL，不存 key

### 悬浮窗信息层级（线框已定稿，assets/token-watcher-wireframe-20261019.png）

今日总量大数字（第一眼）→ 实时心电图折线（最近 1 小时，秒级）→ 模型分布横条 → 订阅档案卡片 → 会话列表；时段 chips（今天/7天/30天/全部）一处切换全局过滤。

**v0.1 配额口径（唯一口径，全文以此为准）**：订阅档案卡片交付**手动额度配置**的配额条（用户填总额度/已用/重置日，标注「手动」）；自动配额（中转 billing 接口拉取、官方启发式估算）进 v0.2。归因时间线之外的时间段（含装工具前的全部历史）统一归入「未知 / Unknown」档案，在订阅区显示为一张置灰卡片（无配额条）——这就是 Premise 3「显示未知时段」的落地位置。

### 菜单栏项（用户指定，可配置）

默认显示**当前激活会话**的总 Token；四指标可配（总/输入/缓存读取/输出）；无活跃会话时回退今日累计。「激活会话」= 最近 5 分钟内有新 usage 记录的会话；**多会话并行时取最近一条 usage 记录所属的会话**（不求和——求和方案并入 Open Question 4 按体感调）。分钟级刷新即可（空闲 CPU≈0），悬浮窗内才秒级。

**双平台呈现**：macOS 用 NSStatusItem 文本 title（Tauri tray title，原生支持）；Windows 系统托盘不显示文本 title，数字**动态渲染进托盘图标**（canvas 画紧凑形式如 `184K` 到 24×24 图标位图，随分钟级刷新重绘），tooltip 放完整数字，点击弹出悬浮窗看全量。Tauri v2 tray 图标热更新能力在实现步骤 3 首先核实。

### 订阅档案识别规则

- 档案主键 = 规范化的 `ANTHROPIC_BASE_URL`（scheme+host+port；path 差异提示不区分）
- 次级键（可选）= `ANTHROPIC_AUTH_TOKEN` 指纹（SHA-256 前 8 位 hex），用于区分同 URL 不同 key 的订阅；**永不持久化 token 原文**，只存指纹
- 显示名用户可编辑，默认从 host 生成（`api.deepseek.com` → `DeepSeek`）；`api.anthropic.com` 默认「Anthropic 官方」
- 无法归入任何档案的时间段 → 「未知 / Unknown」档案（见悬浮窗信息层级）

### 默认主题：Meter Face 合成版（v0.1 唯一预设）

- 底色：暖石墨 #262420（暗）/ #F2EFE9（亮，非奶油）；发丝线分区 #3A3730 / #DFDACD，拒绝卡片阴影堆砌
- 唯一信号色：琥珀 #E8A33D（只给测量：曲线、LIVE 点、活跃刻度；绝不用于 chrome/选中态）
- 诚实编码：**45° 斜线纹理填充=估算，实心=实测/手动**；`est./预估`、`manual/手动` 等宽字标注紧贴数值
- 字体：Archivo（Latin，display 用 wdth 110）+ Fragment Mono（数字）；CJK 回退 PingFang SC / Microsoft YaHei UI（系统字体，不打包）
- 动效：逐位 120ms 上滑（机械寄存器，非老虎机滚轮）；大 burst 最多 3 步 80ms 中间值；折线持续左漂 ~1px/s；空闲 30s 后笔抬起（前导点变空心）；全程兼容 reduced-motion
- 折线诚实语义（Codex 贡献）：缺口=无观测时段；口径标注「Reported tokens/s」（JSONL 批量到达≠精确生成时刻）
- 排除项：全 UI 零象形图标（只用点/斜线/发丝线/进度条四种图形记号）；无红绿评判色；2px 硬倒角；无毛玻璃

### v0.2 路线图

桌面角落 HUD（透明置顶+点击穿透）→ 成本估算（LiteLLM 价格表，1h 缓存）→ 自动配额（官方启发式估算 / 中转 billing 接口拉取；手动额度配置 v0.1 已交付）→ 主题切换器（+Calibrated Slate、+Mint Pulse 预设）→ flight recorder 时间线 → 数据源扩展（Codex CLI ~/.codex/ 等，按 tokscale 适配表逐个来）→ 可选本地代理模式（归因精确到请求，也是同 URL 多 key 的彻底解法）。

## Open Questions

1. 中转站 billing API 格式差异大（new-api/one-api 系 vs 自建）——v0.1 先只做手动额度配置，接口拉取放 v0.2 摸清主流格式再做
2. Claude Code 版本升级可能改 JSONL schema——需要 schema 版本探测与容错解析策略（实现时定）
3. 产品名 token-watcher 是否最终定名（目录名，GitHub 建仓前可改）
4. 激活会话判定的 5 分钟阈值、并行时「取最近」还是「求和」——实装后按体感调
5. 同 base URL 不同 key 的订阅：v0.1 用 token 指纹次级键区分；若 CC Switch 之外的工具把同一地址配多 key 成为常态，考虑提前上 v0.2 代理模式彻底解决

## Success Criteria（v0.1 验收硬指标，来自 Codex 建议并采纳）

1. **悬浮窗**（秒级表面）：fs 事件→数据推送→UI 更新 <2s
2. **菜单栏**（分钟级表面）：用量变化后 ≤60s 内反映（Windows 托盘图标同节奏重绘）
3. 重启应用/重扫文件，总量绝不重复计数（checkpoint+去重）
4. 删除源 JSONL 文件，历史统计仍在（自建 SQLite）
5. macOS 与 Windows 均能构建运行
6. 空闲（无 coding 活动）CPU 占用≈0，无轮询
7. 口径一致性：菜单栏配置为「今日累计」（或处于无活跃会话回退态）时，与悬浮窗大数字完全相等；两个表面的 token 四项（input/output/cache_read/cache_creation）口径定义完全一致
