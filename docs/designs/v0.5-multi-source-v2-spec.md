# v0.5 多数据源扩展规约（OpenCode / Continue.dev / omp 接入）

> 状态：定案  
> 日期：2026-10-21  
> 目标版本：v0.5.0  
> 前置标准：token-watcher-design-v1.1.md、docs/designs/v0.3-multi-engine-spec.md、docs/designs/v0.4-multi-source-spec.md

## 1. 目标与范围

在 v0.3 与 v0.4 中，Token Watcher 已成功接入 **Claude Code**（`~/.claude`）、**Codex CLI**（`~/.codex`）、**Cline**（VS Code 插件）、**Roo Code**（VS Code 插件）与 **Aider**（终端 CLI），建立了跨平台、统一四维 Token 归一化的多源底座。

在 v0.5 中，我们将监控版图进一步扩充至现代开发者生态中另外三款高频主流 AI Agent / 编码工具：
1. **OpenCode**：由 SST / Anomaly 团队打造的高性能全栈终端 & 桌面 AI 编码工具，本地采用 SQLite（`opencode.db`）持久化完整会话与四维用量；
2. **Continue.dev**：开源 VS Code & JetBrains 编码助手事实标准，本地以 JSON 文件树（`~/.continue/sessions/*.json`）持久化交互历史；
3. **omp**：轻量级终端自主 Agent 系统，按项目以 JSONL 格式（`~/.omp/agent/sessions/**/*.jsonl`）记录完整的请求往返与精确 usage。

## 2. 核心架构决议（D31 ~ D35 全部定案）

| 编号 | 级别 | 审查决议与加固规则 |
|---|---|---|
| **D31** | **P0** | **OpenCode 只读 SQLite 增量查询与 WAL 隔离**：<br>OpenCode 运行时会并发写入 `opencode.db`。Token Watcher 必须使用只读标志（`SQLITE_OPEN_READ_ONLY \| SQLITE_OPEN_URI`）与 `PRAGMA query_only = ON;` 打开连接，绝对禁止写操作与长时间锁表；利用 `checkpoints` 表记录 `opencode.db` 对应的最新增量毫秒时间戳 `max_time_created`，仅拉取增量消息；主键命名为 `opencode:{session_id}:{message_id}`。 |
| **D32** | **P0** | **omp 独立项目分层 JSONL 流式接入**：<br>omp 在 `~/.omp/agent/sessions/` 下按项目建立独立子目录，存放 `*.jsonl` 会话日志。复用成熟的 `JsonlDir` 扫描模型与 byte offset checkpoint 增量管道；精准过滤 `type == "message" && message.role == "assistant"` 且含 `message.usage` 的记录行；主键命名为 `omp:{session_id}:{message_id}`。 |
| **D33** | **P1** | **Continue.dev (mtime, size) 增量跳过与全景会话提取**：<br>Continue 每次响应会整体重写当前会话的 `<sessionId>.json`。接入逻辑采用与 Cline/Roo 同构的 `(mtime, size)` 检查点机制，未变更毫秒级跳过；解析时遍历 `history` 提取助手回复及其携带的 `promptLogs` 或 `usage` 四维指标；主键命名为 `continue:{session_id}:{item_index}:{timestamp_ms}`。 |
| **D34** | **P1** | **多根目录独立探测与平滑容错**：<br>在启动及定时对账期间，独立探测 OpenCode、Continue、omp 对应的配置与数据目录；任何一个工具未安装或目录不存在时，静默忽略并记录调试日志，绝不向用户界面弹出虚假错误横幅或打断其他引擎的正常监控。 |
| **D35** | **P1** | **极简工控微徽标矩阵升级**：<br>会话列表与会话飞行记录仪全面接入新徽标：`[OpenCode]`（翡翠绿）、`[Continue]`（青蓝）、`[omp]`（深金黄），保持 9px 等宽字体与 WCAG AA 4.5:1 对比度标准。 |

## 4. 解析与归一化实现契约

### 4.1 OpenCode 解析契约 (`parse_opencode_messages`)

- **数据源表**：`message`（关联 `session` 获取会话元数据）。
- **字段提取**：
  ```sql
  SELECT m.id, m.session_id, m.time_created, m.data, s.title, s.directory
  FROM message m
  LEFT JOIN session s ON m.session_id = s.id
  WHERE m.time_created > ?
  ORDER BY m.time_created ASC
  ```
- **四维归一化**：
  从 `m.data` JSON 字符串中提取：
  - `role == "assistant"`（若为 `"user"` 则忽略）；
  - `model = data.modelID`（兜底 `"opencode-model"`）；
  - `net_input = data.tokens.input`；
  - `output = data.tokens.output`；
  - `cache_read = data.tokens.cache.read`；
  - `cache_creation = data.tokens.cache.write`；
  - 若 `data.tokens` 缺失或字段为负数，严格判定为坏行并丢弃。
- **主键规范**：`opencode:{session_id}:{message_id}`。

### 4.2 Continue.dev 解析契约 (`parse_continue_session`)

- **扫描**：枚举 `~/.continue/sessions/*.json`。
- **结构解析**：
  - 提取 `sessionId`（兜底为文件名去掉 `.json`）与 `workspaceDirectory`；
  - 遍历 `history` 数组中的元素：
    - 筛选 `message.role == "assistant"`；
    - 提取模型名称（优先 `promptLogs[0].modelTitle`，兜底 `model` 或 `"continue-model"`）；
    - 提取时间戳：`timestamp`（若无则按文件 `mtime` 或递增序号微调）；
    - 提取用量：
      - `net_input = promptTokens`；
      - `output = completionTokens`；
      - `cache_read = 0`（Continue 若未分离则记 0）；
      - `cache_creation = 0`。
- **主键规范**：`continue:{session_id}:{index}:{timestamp_ms}`。

### 4.3 omp 解析契约 (`parse_omp_line`)

- **扫描**：递归枚举 `~/.omp/agent/sessions/**/*.jsonl`。
- **结构解析**：
  - 识别 `type == "message"` 且 `message.role == "assistant"`；
  - 提取 `message.usage`：
    - `net_input = usage.input`；
    - `output = usage.output`；
    - `cache_read = usage.cacheRead`；
    - `cache_creation = usage.cacheWrite`；
    - `model = message.model`（或根级 `model`）；
  - 时间戳：解析 ISO-8601 字符串 `timestamp` 转为毫秒。
- **主键规范**：`omp:{session_id}:{message_id}`。

## 5. 管道扩展与生命周期管理

### 5.1 数据路径聚合 (`DataPaths`)
在 `src-tauri/src/watch.rs` 的 `DataPaths` 中增加：
- `opencode_db_path: PathBuf`
- `continue_sessions_root: PathBuf`
- `omp_sessions_root: PathBuf`

### 5.2 首扫与增量监听
1. **首扫**：
   - 增加对 `opencode_db_path`、`continue_sessions_root`、`omp_sessions_root` 的存在性检查；
   - 存在则纳入第一轮首扫，向前端发射 `scan-progress`；
2. **FSEvents 监听**：
   - `opencode.db`：监听父目录或数据库文件，变更时触发增量 ingest；
   - `continue_sessions_root`：非递归/递归监听会话目录；
   - `omp_sessions_root`：递归监听 `*.jsonl` 文件变更。
