# v0.2 桌面角落 HUD 模式（Desktop Corner HUD）设计规约

> 状态：已定案（经 Codex & agy 双模型第二意见审查与工程加固）  
> 日期：2026-10-20  
> 目标版本：v0.2.0  
> 前置决策：双窗共存架构 + 紧凑双段胶囊 + 托盘穿透切换 + 双模型 P0~P2 加固定案

---

## 1. 为什么需要桌面角落 HUD

在 v0.1 中，Token Watcher 提供了托盘常驻数字（macOS 菜单栏）与 380×560 悬浮主面板：
- **Windows 系统痛点**：Windows 任务栏托盘区域仅能容纳 16~20px 的静态小图标，无法常驻绘制清晰数字（数字入图标方案在 v0.1 论证后已被否决）。Windows 用户必须将鼠标悬停在托盘图标上看 tooltip，或点击弹出 380×560 大窗口，缺乏即时视觉感知。
- **沉浸式编码痛点（VibeCoding）**：开发者全屏或分屏高频使用 Claude Code 时，注意力集中在代码编辑器与终端。频繁切换窗口打断心流；托盘距离视线焦点较远。

**桌面角落 HUD 模式是双平台常驻监视的完整解决方案**：
借鉴游戏 FPS 帧率计数器的设计，在屏幕角落提供一个超轻量、置顶、半透明无边框的「微型仪表胶囊」。
- 面积小（约 184×34px），视觉噪声降到最低；
- 支持任意拖拽位置，并自动跨会话记忆坐标；
- 提供「锁定穿透」模式，鼠标点击直接穿透到背后的编辑器，绝对不阻碍打字与交互；
- 与主面板无缝联动：单击未锁定的 HUD 即可唤醒主仪表盘，主面板关闭/收起后 HUD 继续平稳运行。

## 2. 核心架构设计

### 2.1 双窗口架构与数据流

```
+-----------------------------------------------------------------------------------------+
|                                    Tauri 核心进程                                        |
|                                                                                         |
|  +------------------------------+             +---------------------------------------+ |
|  |     主窗口 (label: "main")    |             |        HUD 窗口 (label: "hud")        | |
|  |     380×560 常规悬浮窗       |             |        184×34 无边框置顶透明小窗       | |
|  |     (详细报表/卡片/图表/设置) |             |        (紧凑双段胶囊: 速率 + 累计)    | |
|  +------------------------------+             +---------------------------------------+ |
|                 ^                                                 ^                     |
|                 | (聚焦时才做全量查询)                             | (轻量 HUD 查询/增量)  |
|                 +-----------------------+-------------------------+                     |
|                                         | 广播事件 (emit)                               |
|                                         | (dashboard-dirty / usage-pulse)               |
|                                         |                                               |
|                    +------------------------------------+                               |
|                    |  数据线程 (Watch / Ingest Pipeline) |                               |
|                    |  - main 或 hud 任意一个可见时保活   |                               |
|                    |  - 避免隐藏主窗在后台空转消耗 CPU   |                               |
|                    +------------------------------------+                               |
+-----------------------------------------------------------------------------------------+
```

### 2.2 双模型审查加固裁决（P0 ~ P2）

#### 1. 材质与透明度真实表现（P0-1 加固）
- **事实**：WebKit (macOS) 与 WebView2 (Windows) 的沙箱机制决定了 CSS `backdrop-filter: blur()` **无法对宿主操作系统（桌面/其他应用）的像素进行高斯模糊**，且在 Windows 上容易引起黑框或频闪。
- **裁决**：直接采用纯深色高对比半透明材质 `rgba(22, 24, 29, 0.90)`，配合 `1px solid rgba(255, 255, 255, 0.12)` 与微弱高光边框、柔和 CSS `box-shadow`。两平台视觉完全统一，零 GPU 额外模糊损耗，极度清晰克制。

#### 2. 坐标类型与 Rust `Eq` 派生（P0-2 加固）
- **事实**：`AppSettings` 派生了 `Eq`，若字段为 `Option<f64>` 会导致 Rust 编译失败（`f64: Eq` not satisfied）。
- **裁决**：窗口逻辑坐标必须采用离散整数 `Option<i32>`：
  ```rust
  #[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
  #[serde(default)]
  pub struct AppSettings {
      pub tray_metric: TrayMetric,
      pub hud_visible: bool,
      pub hud_locked: bool,
      pub hud_x: Option<i32>,
      pub hud_y: Option<i32>,
  }
  ```

#### 3. 主窗口关闭语义与生命周期（P0-3 加固）
- **事实**：现存代码在点击主窗口关闭按钮（X）时默认会销毁窗口，导致托盘再次无法呼出主窗口，甚至导致整个进程意外退出。
- **裁决**：在 `on_window_event` 中拦截 `main` 窗口的 `WindowEvent::CloseRequested`，调用 `api.prevent_close()` 并隐藏窗口（`window.hide()`）。关闭主面板仅将其隐入托盘，HUD 窗口平稳存活；完全退出仅走托盘「退出」菜单项。

#### 4. Tauri 2 `capabilities` 权限 ACL 补齐（P1-1 加固）
- **事实**：`capabilities/default.json` 之前仅配置了 `windows: ["main"]`。若不加入 `"hud"`，HUD 窗口内的事件监听与窗口拖拽会被静默拒绝。
- **裁决**：修改 `capabilities/default.json`，将 `windows` 明确包含 `["main", "hud"]`。

#### 5. 跨多显示器、分辨率切换与拔屏越界保护（P1-2 加固）
- **事实**：拔掉高分辨率外接显示器后，保存的坐标可能飞出虚拟屏幕外，导致 HUD 变为不可见且无法拖回的幽灵窗口。
- **裁决**：
  1. 窗口位置恢复时枚举 `app.available_monitors()`，校验 saved 矩形 `[x, y, x + 184, y + 34]` 是否与至少一个可用屏幕的 `work_area` 有有效交集（≥ 32px）；
  2. 若未命中或屏幕拓扑失效，安全回退到当前主屏幕的右上角：`x = work_area.position.x + work_area.size.width - 184 - 24`, `y = work_area.position.y + 24`；
  3. `save_hud_position` IPC 指令在后端校验输入范围，防非法坐标。

#### 6. 拖拽与单击主面板的事件冲突解决（P1-3 加固）
- **事实**：`data-tauri-drag-region` 吞噬 DOM `click` 事件，或在拖动释放时误触发 `click` 导致弹出大面板。
- **裁决**：
  - 胶囊内子元素文本设置 `pointer-events: none`；
  - 前端监听 `pointerdown` 记录起始时间戳和窗口位置；在 `pointerup` 时对比当前窗口位置：如果窗口坐标未改变且按压时间小于 300ms，判定为用户单击，调用 `show_main_window`；如果窗口发生了位移（说明用户在拖拽），则只触发 `save_hud_position`，绝不弹起主窗口。

#### 7. Windows 穿透恢复刷新（P1-4 加固）
- **事实**：Windows 下 `set_ignore_cursor_events(false)` 解除穿透时，WebView2 存在命中测试未即时刷新的历史兼容性问题。
- **裁决**：解锁分支在 `set_ignore_cursor_events(false)` 后，追加 `hud_window.set_focus()` 或重新声明 `set_always_on_top(true)`，强制触发 DWM z-order / hit-test 重排。

#### 8. 后台隐藏主窗口降噪（P1-5 加固）
- **事实**：数据线程若在 HUD 显示时广播 `dashboard-dirty`，隐藏的主窗口若盲目重拉数据，会产生昂贵的 5 表关联查询。
- **裁决**：
  - 主窗口 `App.svelte` 内部感知自身是否可见（通过窗口 focus / blur 或 Tauri 状态）：在隐藏期间仅记录 `dirty` 标志，不发网络/IPC 请求；等到主窗被呼出/聚焦时才一次性水合刷新。
  - HUD 只调用轻量的 `get_hud_summary` 命令（仅查询今日累计与最近 5 分钟脉冲速率），耗时 < 1ms。

#### 9. 单一写者配置持久化（P1-6 加固）
- **裁决**：`AppSettings` 的修改统一在 Rust 端通过应用状态互斥锁保护，由专门的原子读写方法处理，杜绝托盘线程与拖拽保存线程之间的 read-modify-write 丢字段问题。

#### 10. macOS 全屏空间限制声明（P2 说明）
- **说明**：macOS 原生全屏（Green Button Space）下，操作系统限制普通非 Panel 浮动窗口跨 Space。全屏 Space 下用户依然可通过菜单栏数字进行监控；HUD 在普通桌面、分屏及各大平铺窗口管理器（如 Aerospace/Yabai）下均置顶常驻。

## 3. 界面表现与设计语言（Meter Face）

### 3.1 尺寸与样式
- 尺寸：宽 `184px`，高 `34px`；
- 材质：`rgba(22, 24, 29, 0.90)` 高对比暗色质感背景，`1px solid rgba(255, 255, 255, 0.12)` 微弱边框，外加 `0 8px 24px rgba(0, 0, 0, 0.35)` 柔和阴影；
- 圆角：`9999px` 胶囊药丸轮廓；
- 字体：等宽机械字体，延续 Meter Face 视觉风格。

### 3.2 布局分布
```
┌──────────────────────────────────────────────┐
│   ⚡️  14.2k/m    │    359,420  (或 359K)    │
└──────────────────────────────────────────────┘
  <-- 燃烧速率 -->   分   <-- 今日累计用量 -->
                    割
                    线
```
- **左侧燃烧速率**：
  - 聚合过去 5 分钟的有效脉冲折算成每分钟速率（`tokens/min`），格式化为 `14.2k/m`；
  - 空闲时显示 `-` 或 `0/m`；
- **右侧累计用量**：
  - 显示今日总 Token，到达新脉冲时触发数字上滑微动画；
  - 颜色延续主题唯一信号色——暖琥珀色（`#f59e0b` / `var(--accent)`）。

## 4. 设置契约与 API 接口

### 4.1 `app_settings.rs`
```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(default)]
pub struct AppSettings {
    pub tray_metric: TrayMetric,
    pub hud_visible: bool,
    pub hud_locked: bool,
    pub hud_x: Option<i32>,
    pub hud_y: Option<i32>,
}
```

### 4.2 前后端 IPC Commands
1. `get_hud_summary() -> HudSummary`: 返回 `{ total_today: i64, rate_per_min: i64, hud_locked: bool }`
2. `set_hud_visible(visible: bool) -> Result<(), String>`
3. `set_hud_locked(locked: bool) -> Result<(), String>`
4. `save_hud_position(x: i32, y: i32) -> Result<(), String>`
5. `show_main_window() -> Result<(), String>`
